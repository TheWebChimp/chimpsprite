# Modelos 3D, parte 1 (núcleo y sprites): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Artboards 3D en el lienzo (modelo low-poly con textura de un artboard), render pixel por
software con luz de rampas y contorno, panel del dock, y *Bake* a artboards de sprites.

**Architecture:** El modelo (`Model3D`) vive en `cs-core` como campo opcional del `Artboard`, en
enteros de punto fijo. Un crate nuevo `cs-3d` (solo depende de `cs-core`) tiene las primitivas y
el rasterizador. `cs-render` compone un artboard 3D renderizando su modelo en `materialize` y en
las instancias, así que lienzo, miniaturas, símbolos y exportación lo ven sin cambios. Los cambios
son `DocCommand::SetModel` con undo; la estructura del artboard 3D queda bloqueada como la de las
fuentes (el `FontLock` se generaliza a `StructureLock`).

**Tech Stack:** Rust (edition 2024), egui/eframe 0.36 (wgpu), serde, el UI kit propio.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-11-01-3d-core-design.md`.
- **Simplificación aprobada al planear:** el sprite de un artboard 3D tiene **1 capa y 1 frame**. En
  el lienzo, las miniaturas y los símbolos se ve con el **frame 0** de la textura; la textura
  animada se usa al **hornear** (frame N del bake ← frame N de la textura).
- **Rampa de luz:** "un paso más oscuro" de un color `c` = el color de la paleta del documento con
  luminancia menor que `c` más cercano a `c` en distancia RGB (sin contar transparentes); si no hay
  ninguno, `c`. La luminancia es `299·r + 587·g + 114·b`. Dos pasos = aplicar dos veces.
- **Sin floats guardados:** `Model3D` y lo que contiene derivan `Clone, Debug, PartialEq, Eq, Hash,
  Serialize, Deserialize`; posiciones y vértices en `i32` de 1/16 de unidad (`FIXED = 16`), ángulos
  en `i32` décimas de grado, escalas en `i32` milésimas (1000 = 1). `cs-3d` puede usar `f32` al
  calcular, nunca en lo que se guarda.
- `cs-core`, `cs-3d`, `cs-commands`, `cs-render`, `cs-tools` sin egui (compilan a wasm); agregar
  `-p cs-3d` a la lista wasm de `.github/workflows/ci.yml`.
- Textos de UI en inglés ("New 3D Model…", "3D", "Bake…"); comentarios y docs en español.
- `cargo fmt` y `cargo clippy --all-targets` sin avisos antes de cada commit; commits en español con
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Nunca `git checkout -- …`, `git restore`, `git stash`, `git reset --hard`, `git clean`; solo
  `git add <archivos propios>`. No tocar `.design/` (el usuario trabaja ahí).
- Toolchain: `export RUSTUP_HOME=/d/Work/chimpdeas/.rust-toolchain/rustup CARGO_HOME=/d/Work/chimpdeas/.rust-toolchain/cargo; export PATH=$CARGO_HOME/bin:$PATH CARGO_BUILD_JOBS=8`

### Task 3: El rasterizador (`cs-3d`)

**Files:**
- Create: `crates/cs-3d/src/raster.rs`, `crates/cs-3d/src/ramp.rs`

**Interfaces — Produces:**
```rust
pub struct Texture<'a> { pub width: u32, pub height: u32, pub pixels: &'a [Rgba] }
pub struct RenderInput<'a> {
    pub model: &'a Model3D,
    pub size: (u32, u32),
    pub texture: Option<Texture<'a>>,   // None: caras de un gris medio (128,128,128)
    pub palette: &'a [Rgba],           // para la rampa de la luz
    pub camera: Option<Camera3D>,      // None: la del modelo
    pub extra_yaw: i32,                // décimas de grado sumadas a la rotación Y de todos los objetos (Bake)
}
pub fn render_model(input: &RenderInput) -> Vec<Rgba>     // size.0*size.1, fondo transparente
pub fn darker(palette: &[Rgba], c: Rgba) -> Rgba          // ramp.rs, regla de Global Constraints
pub fn pick_object(input: &RenderInput, x: u32, y: u32) -> Option<usize>  // objeto bajo el pixel (para el clic)
```
Algoritmo:
1. Matriz de cada objeto: escala (milésimas) → rotación X, Y (+`extra_yaw`), Z (décimas de grado) → traslación. Vértices de `FIXED` a `f32`.
2. Vista: la cámara orbita `target` a `distance`, con `yaw` alrededor de Y y `pitch` hacia arriba. Proyección: perspectiva (`fov`) o ortográfica (escala: la altura visible es `distance`·2 unidades). Centro de la imagen = target.
3. Por cara: si la normal en espacio de vista mira lejos de la cámara y el objeto no es `double_sided`, se salta. Quads → 2 triángulos. Rasterizar con regla top-left, z-buffer (lo más cercano gana), UV con corrección de perspectiva, muestreo *nearest* (`floor`) con `rem_euclid` del tamaño de la textura. Texel transparente → no pinta.
4. Luz (si `enabled`): dirección desde `yaw`/`pitch`; `d = dot(normal, -luz)`; pasos: `d > 0.5` → 0, `d > 0.0` → 1, si no → 2; aplicar `darker` esos pasos al texel.
5. Contorno (si `Some(color)`): todo pixel transparente con un vecino de 4 conexión opaco se pinta del color.

- [ ] **Step 1:** Pruebas con imágenes chicas (8×8 o 16×16):
  - un cubo de frente (preset Front, sin luz, textura de un color) cubre un cuadrado centrado y todo pixel opaco es ese color;
  - con luz desde la derecha (yaw 900, pitch 0), en preset Iso las tres caras visibles dan 0/1/2 pasos (tres colores distintos de la paleta);
  - `darker`: con paleta `[negro, gris, blanco]`, `darker(blanco) == gris`, `darker(negro) == negro`;
  - un plano visto por detrás no se ve; con `double_sided` sí;
  - contorno: un pixel transparente pegado al cubo tiene el color del contorno, uno lejano sigue transparente;
  - la UV: una textura 2×1 roja|azul en un plano de frente da mitad izquierda roja y derecha azul;
  - `pick_object` devuelve el índice del objeto en el centro y `None` en una esquina vacía.
- [ ] **Step 2:** Correr → falla.
- [ ] **Step 3:** Implementar `raster.rs` y `ramp.rs`.
- [ ] **Step 4:** Verde.
- [ ] **Step 5:** Commit "Modelos 3D: el rasterizador pixel (z-buffer, UV, luz de rampas, contorno)".
